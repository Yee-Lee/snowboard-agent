# P9.1-REALISTIC-TURN-RESIDENCY-DESIGN-001

Status: `USER APPROVED / IMPLEMENTATION AUTHORIZED`

## 1. Decision and purpose

The User identified the original P9 full-session overlap method as a design
defect on 2026-08-25 and directed Audio POC to propose P9.1. After explicit User
confirmation on 2026-08-25, P9.1 replaces the original P9 test for Audio M4. The rejected run
and raw evidence remain immutable history and receive no M4 credit.

P9.1 proves the realistic non-streaming turn lifecycle: all Audio finalists and
the LLM memory reservation coexist, while CPU-heavy ASR, LLM inference and TTS
run in their actual sequential order. It does not claim product-composition or
LLM Gate 2B credit.

## 2. Frozen P9.1 sequence

Load Silero VAD, base-Q8 ASR and Matcha TTS once. Start the unchanged,
checksum-locked P9 surrogate once so its `2304 MiB` reservation remains resident
for the entire catalog. Then run each of the 20 locked sessions as follows:

```text
P9 supervisor + 2304 MiB reservation remain resident
  -> VAD
  -> ASR terminal result
  -> P9 INFER: four CPU workers run for 6.0 s
     (all three Audio finalist processes remain resident and alive)
  -> matched P9 INFERENCE_COMPLETE
  -> deterministic Reasoner mapping
  -> TTS generation
  -> pinned Core AudioOutput physical playback completion
```

ASR is not concurrent with simulated LLM inference because the LLM consumes the
ASR result. TTS is not concurrent because it consumes the LLM result. This is
the current POC's non-streaming product sequence. Streaming decode/TTS,
barge-in, AEC and wake word remain out of scope.

## 4. PASS gate

P9.1 is `PASS` only when one clean authorized run proves all of the following:

1. Exact Audio/Core SHAs, candidate artifacts, P9 hashes and isolated runtime
   manifests match before launch.
2. VAD, ASR and TTS each load once; their process identities remain unchanged
   through all 20 sessions.
3. Every ASR terminal result is non-empty before its corresponding `INFER`.
4. Every `INFER` emits four live worker PIDs, runs for the locked six seconds,
   returns the matching `INFERENCE_COMPLETE`, and leaves all Audio finalists
   alive without reload.
5. Every TTS result completes physical playback after the corresponding P9
   completion.
6. Samples at intervals no greater than `0.5 s` retain `swap=0`,
   `MemTotal - MemAvailable <= 3584 MiB`, `throttled=0x0`, and contain no OOM,
   memory-pressure event, crash or disqualifying xrun.
7. Shutdown restores child processes, threads, file descriptors, iterators,
   streams, tasks and Audio device owners to the recorded baseline.

A valid gate breach is `FAIL`; invalid preconditions are `BLOCKED`; evidence
loss after start is `INCONCLUSIVE` only when a deterministic result is
impossible. Results remain `DRAFT_USER_CONFIRMATION_PENDING` until reviewed by
the User.

## 5. Required implementation before execution

After User design confirmation, Audio POC will:

1. version the P9.1 policy/test ID in the packet, schema and validators;
2. move the P9 `INFER` interval between ASR completion and Reasoner/TTS;
3. record stable Audio PIDs/load counts immediately before and after every
   `INFER`;
4. preserve partial resource samples and stage timings on failure;
5. bind `OPENBLAS_NUM_THREADS=1` in the controller launch environment and prove
   the observed resampler thread count remains `1 -> 1` without changing wheel
   versions;
6. add local success, ordering, liveness, protocol and fail-closed regressions;
7. cut and push a new immutable candidate, then request exact-SHA User execution
   authorization;
8. run P9.1 first on Pi. Only a reviewed P9.1 result permits the independent
   offline 20-session combined run and the 12 failure cases to continue.

## 6. User confirmation

The User replied `ok agree` on 2026-08-25. P9.1 therefore supersedes the original
P9 method for Audio M4 and the implementation work in section 5 is authorized.
This confirmation does not pre-authorize an unknown future candidate SHA or
