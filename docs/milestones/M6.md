# M6 規劃

## 8. M6 ── 語音喚醒、視覺輸入與整體收斂

### 8.1 範圍

* 實作獨立 wake daemon 與 `input_events/voice_wake` IPC client。
* 在 `docs/protocol.md` 定義 wake daemon 的版本、detected event、suspend / resume、`ensure_released()`、ACK、error 與 shutdown schema。
* 落實單一麥克風 owner ：WAKE Entry 取得 suspend ACK 或 daemon exit proof 後才允許 Listen 開始；無 release proof 時 fatal。
* 實作真實 Vision adapter 與 Look worker，使用 M3 Camera HAL。
* 驗證 button、wake word、external message 三種入口，以及 listen / read / look 組合的完整 session。
* 完成長時間重複 session、shutdown、recovery 與 log hygiene 的整體驗收。
* 維持 Display Baseline ；整體收斂後不得留下 fullscreen owner 或 Display client task。

### 8.2 相依

* M5 驗收通過。
* `model_spec.md` 的 M6 baseline 已固定 wake-word / Vision engine、model、授權、版本、checksum、Pi 安裝與 benchmark 證據。
* Wake daemon process owner / service 方式已固定。
* Wake daemon wire schema 已 review ；測試環境可觀察 daemon PID 與 ALSA ownership。

### 8.3 排除項目

* 不支援同時由 wake daemon 與 Listen 錄音。
* 不加入 camera stream / video、gesture recognition 或 runtime format 切換。
* 不加入 touch、LED 表達、adjuster overlay、一 pin 多訂閱者。
* 不加入 Display Complete profile 的正式資產與動畫；這些屬 M7。
* 不加入 `arch.md` §8 尚未定案的 query、完整 reasoning loop 與跨 session 記憶。
* 不把本階段等同正式產品發行；systemd unit、映像製作、OTA 與 release packaging 另案規劃。

### 8.4 可重複驗收

1. 在 Raspberry Pi 5 執行：

```bash
python -m pytest -v
```

2. 驗收至少證明：
* wake daemon active 時主 process 不持有 mic ；suspend ACK 或 exit proof 先於 Listen `frames()` ；回 IDLE 且 in-flight 空後才 resume。
* suspend 失敗會執行 `ensure_released()` ；release proof 失敗時 Listen 從未啟動且 process 走 fatal，不出現雙 mic owner。
* Vision 對固定 camera fixture 產生非空描述；timeout / adapter failure 分別走 P5 或 ERROR + recovery 契約。
* 三種 wake source 的 first-turn mapping 正確，後續 turn 可依 reasoner 選擇合法的 listen / read / look 組合。
* 連續執行 20 個固定 fixture session 後，沒有 orphan child / daemon、未清 in-flight、未關 read window 或未釋放 fullscreen owner。
* Shutdown 在各 state 均拒絕新 wake、完成可證明的收斂並依規則 exit 0 ；刻意觸發 Level 3 時 exit 4。
