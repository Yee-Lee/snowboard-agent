# M4 規劃

## 6. M4 ── 本機 AI 語音主線

M4 是單一 milestone，但包含三個可追溯的子 gate：M4a Audio、M4b LLM、M4c Session Display。M4a 與 M4b 可在各自輸入 Accepted 後並行準備；M4c 必須等 M4a、M4b 都通過，才能以真實 session 資料完成顯示接線。只有三個子 gate 都在同一產品 delivery exact SHA 通過，M4 才可標記 Accepted。

### 6.1 範圍

#### M4a ── Local Audio

* 實作真實 ASR 與 TTS adapter，格式與 M3 已驗收的 Audio HAL config 一致。
* 固定 WAV fixture 可產生非空 ASR result；固定文字可產生格式正確的 TTS PCM 並完成播放。
* 固定 ASR / TTS engine、model、voice、版本、授權、checksum、Pi 安裝方式及 benchmark evidence。
* Audio POC Gate 2A selection ACK只放行adapter scaffold；Gate 2B `POC Accepted` final handoff固定reference package / conformance kit後，才可鎖定production dependency / model / voice並進產品acceptance。
* Core Gate 3逐項記錄POC evidence inheritance與product-delta；候選比較不無理由重跑，但adapter / HAL wiring、config / lock / packaging、RM / SM lifecycle、composition、resource、offline及產品SHA regression必須重驗。

#### M4b ── Local LLM

* 實作 LiteRT-LM persistent child process、READY handshake、單 turn Conversation、result / timeout / shutdown。
* 在 backend 實作前建立 `docs/protocol.md`，定義 child protocol version、READY、generate、stream / result、cooperative cancel、error 與 shutdown wire schema。
* 實作 child `force_abort()` 的 terminate / kill / waitpid completion proof，以及 Resource Manager rebuild / recovery barrier。
* 固定 LiteRT-LM artifact、版本、授權、checksum、Pi 安裝方式及 benchmark evidence。
* POC輸出必須先經Core product validator正規化為`LLMResponse(action_kind, action_payload, next_perceptions)`；模型只產`speak/tool/rest` intent，不執行tool handler。空輸出、拒答、壞JSON與unknown action走P5 apology-speak或rest fallback，prompt / raw output / payload不得進log。

#### M4c ── Session Display

* 完成 Button → Listen → ASR → Reasoner → LiteRT-LM → Speak → TTS → Rest 的 Raspberry Pi 5 離線主線。
* 依 `display_spec.md` 將已驗證的 state、Perception、Tool、Speak、Interrupt 與 sanitized Error 投影至 M3 已驗收的 Display HAL、Renderer / Arbiter。
* Tool 畫面只驗證 sanitized display intent / fixture；實際 ToolRegistry handler 與外部派發仍屬 M5，不因 M4c 提前實作。
* 實作 `SET-SHOW-SESSION-CONTENT` 的 startup config mapping；關閉後不得改變 session、action、audio、resource lifecycle 或 exit code。
* Startup / shutdown 維持 Fullscreen Blank；不加入 Progress、動畫、正式 icons 或完整對話歷史。
* SSD1351正常stop在native handle有效時best-effort present一個全零RGB565 full frame後才close；present失敗仍須完成handle / GPIO / SPI cleanup，重複stop冪等。Acceptance runner在正常完成、任一卡失敗或中斷時都必須執行final Display shutdown。

#### 6.2.1 M4a / M4b POC convergence without circular dependency

1. Audio與LLM先各自完成Gate 2A standalone qualification，可平行進行；selection / provisional ACK只放行不鎖artifact的Core scaffold。
2. Audio POC以Core核准的deterministic M4b resource surrogate完成internal M4，經review成為`POC Accepted` final reference package；不等待LLM final winner，因此不形成循環依賴。
3. LLM Gate 2B再引用該Accepted Audio package執行P9 residency與P10B 20-session combined gate，產生LLM final winner ACK。
4. Core在兩邊final input齊備後更新`model_spec.md`、完成`docs/protocol.md` review並建立產品candidate；POC evidence只作immutable reference，Core Tester仍驗產品exact SHA。
5. 任一Gate 2B發現winner、resource、offline、lifecycle或license Blocking時，停止受影響baseline lock / acceptance並走change request；未受影響的protocol / fake scaffold可繼續，但不得宣稱Accepted。

### 6.3 排除項目

* 不讓 LiteRT-LM 自動執行 Python tool handler；模型只回傳 tool intent。
* 不保留跨 turn / 跨 session 隱藏 conversation history。
* 不實作雲端 LLM、query action 或完整 reasoning loop。
* 不把 native blocking inference 放在主 process thread。
* 不要求 MQTT、voice wake 或 Vision 路徑完成。
* 不加入 Progress UI、Display 動畫、正式 icons 或 pixel-level polish。

### 6.4 可重複驗收

1. 候選驗收順序不可調換；完整操作及 runner contract 見 `docs/runbooks/candidate_hardware_gate.md`：

```bash
# Developer fast loop（團隊主要版本）
python -m pytest -v <affected-nodes>

# Candidate portable gate（CI / 集中環境，三版本執行同一 suite）
python3.11 -m pytest -v -m "not rpi" <M4-portable-suite>
python3.12 -m pytest -v -m "not rpi" <M4-portable-suite>
python3.13 -m pytest -v -m "not rpi" <M4-portable-suite>

# 完整 SHA freeze 且 Pi preflight PASS 後，Pi 3.13 只執行一次正式 gate
python3.13 -m pytest -v -m rpi tests/milestones/test_m4_local_voice.py
```

上列是 test-spec 定稿前的命令形狀，不授權 runner 從目前 HEAD 推導 candidate。正式命令由 candidate gate runner加入bounded timeout、外部SHA / run ID與新output；failure保存result及raw log。Debug可按需要執行，但其結果不得標記或合併為正式Pass。

2. M4a 至少證明：

* 固定 WAV fixture 可產生非空 ASR result；固定文字可產生格式正確的 TTS PCM 並完成播放。
* AudioInput delivered stream / ASR格式一致，TTS / AudioOutput stream格式另行一致；除M3核准的AudioInput HAL native→stream adaptation外，Listen / ASR / TTS / Speak不在runtime隱式resample。
* M4a 與 M4b 同時常駐時仍符合 target-device resource budget。
* Gate 3 evidence index逐項列出Accepted Audio POC SHA / kit revision、繼承理由及產品delta Test ID；不得只寫「沿用POC」。

3. M4b 至少證明：

* LiteRT-LM `start()` 只在 READY ACK 後 return；連續兩 turn 不重載 engine，也不沿用隱藏 Conversation history。
* 模型 timeout、拒答或壞 JSON 在 clean stop 時走 P5 fallback。
* Cooperative cancel 失敗時 Level 2 終止並 waitpid child；recovery barrier 清除前 SM 不回 IDLE、不接受新 wake。
* Rebuild 失敗 / timeout 進 Level 3、exit 4；測試結束沒有 orphan child。
* 固定catalog涵蓋`speak/tool/rest`、capability allowlist、空輸出、拒答、壞JSON、unknown action / tool；正常schema 100%通過，失敗輸出走P5且log不含prompt、raw output或payload。
* Native cooperative cancel不可用但Level 2 terminate→kill→waitpid→rebuild / READY barrier成功時，候選仍可eligible；Level 2或rebuild失敗才進Level 3。

4. M4c 至少證明：

* Display 只呈現目前 session / turn 的已驗證內容；不顯示 credential、prompt、hidden context、raw tool arguments 或 raw model output。
* `SET-SHOW-SESSION-CONTENT=false` 時隱藏 Perception / Tool / Speak，但 State、Error 與 Blank 仍依規格運作。
* Fullscreen ownership、Error clear、Interrupt clear 與回 IDLE 行為符合 `display_spec.md`；Display failure 不阻斷語音主線或改變 exit code。
* Host bridge證明SSD1351 stop成功路徑恰好present一次最終全黑frame後close，failure路徑仍close / release；Pi shutdown observation證明正常完成、測項失敗與中斷後OLED均保持全黑。
* 整條離線語音 session 不需網路，且 log 不含 transcript、prompt 或 raw model output。

5. M4 milestone conclusion 必須列出 M4a、M4b、M4c 各自 result locator，並共同引用同一被測產品 SHA；另引用三版本 portable matrix index與Pi preflight。正式target result使用單一acceptance run ID，不得把debug結果列為Pass。
