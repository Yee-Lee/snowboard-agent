## 6.1 Scope and role boundary

| Slice | Required product behavior | Excluded |
| :--- | :--- | :--- |
| M4A | 真實VAD/ASR/TTS與Audio HAL；維持Accepted identity/config/license/offline evidence | 不重開M4A-only target驗收 |
| M4B | 最小Reasoner、短句理解/回答、session內追問、Reasoner選next_perceptions、end/P5/cancel/recovery | 無tool dispatch、通用task/context manager、跨session恢復、摘要／檢索 |
| M4C | Button→Listen/ASR→Reasoner/LLM→Speak/TTS、Rest與Display完整離線接線 | 無camera/look、MQTT、voice wake、動畫/Progress |
| ALPHA | 同一voice-only能力的廣泛品質、重複使用與穩定性收斂 | 不把M4欠缺的基本Reasoner留到此時才設計 |
| M5 | 實際工具/外部訊息；confirmation與handler policy另定 | M4不提前驗真實tool品質 |

M4語意範圍：身分「雪板，你的語音小助理」、簡短一般知識、當前能力、
澄清/追問、明確結束。答案須基本正確、無虛構能力、能承接前文。
runtime Conversation可在一session內保留history；Core只管理lifetime/capacity，
「不建立記憶系統」不得再解釋為「每turn必須清空」。
M4模型只產text/end，Reasoner產action與next_perceptions；SM擁有session與派發。
Tool fixture只保護generic seam/Display intent，不執行handler。

## 6.3 Acceptance boundary

### Product interaction

普通短句對話：使用者最後speech end→第一個有內容回答audible onset；
2秒目標、初始上限3秒，工具場景排除。不能用ASR API call、內部TTFT、
first PCM write、提示音或固定「請稍候」代替。
Cold startup無產品SLA；完整recovery目標10秒包含清理/verification/load/選定prewarm，
不可將完整rehash移出計時而宣稱達標。操作仍有bounded watchdog。
Input音長、user-new token、output短句與session容量待POC凍結；32只是候選值。
複雜度由case類別界定，超範圍明確要求缩短/拆分，不偷偷截斷。

### Automatic and manual evidence

自動驗schema、Reasoner policy、capability、single Fact、session/cancel/recovery/identity、
timing/resource/offline/privacy。Semantic intent用injected values測policy，
不能宣稱mock證明模型理解。
人工以固定rubric驗identity、knowledge、capability honesty、follow-up coherence、
brevity/end intent；不用keyword/逐字範例或LLM judge代替。
自介／天空／視覺問答是development例，另有未調參holdout。
所有正常performance credit必須同時是有效回答；fallback/錯誤/失去前文不是快回答PASS。

### Resource and lifecycle

同session多turn保留Conversation，跨session無舊context；rest/interrupt/error/shutdown
皆close，尚未THINK也清登記。Dirty/容量不足明確結束，不能silent reset續同session。
MemAvailable為capacity主訊號，owner PSS歸因；移除fixed8/48、
mandatory三generation與過早baseline64MiB gate。
20-session自然soak保留所有樣本、同SHA real Audio+LLM；受控recovery另驗。
新的穩態窗口/reserve需freeze；historical r14 vector/result不改。
維持zero swap/OOM、thermal、process/descendant/ALSA cleanup與no network requirements。

### Display

沿用display_spec.md的目前session/turn驗證內容與SET-SHOW-SESSION-CONTENT privacy。
Startup/shutdown Fullscreen Blank；無Progress/動畫/icons/history UI。
SSD1351stop先best-effort呈全黑frame再close；failure/interrupt也清GPIO/SPI/ownership。
Display failure不改語音/資源lifecycle。Tool只是sanitized fixture，handler留M5。

## 6.4 Target revision and candidate flow

未達性能/資源目標：先確認量測有效、記錄miss與瓶頸，再提出優化、階段性達成、
支援範圍或目標調整；需USER採用的產品變更另記決策。
不因單一miss判模型淘汰／M4取消／整個計畫no-go。
保留old target/raw result/change reason/new target/approval；新標準只適用新revision，
不能回填舊結果為Pass。未處置差異維持Pending，不提前宣稱Accepted。
