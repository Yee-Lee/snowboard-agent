# M4 規劃

## 6. M4 ── 本機 AI 語音主線

### 6.1 範圍

* 實作真實 ASR 與 TTS adapter，格式與 Audio HAL config 一致。
* 實作 LiteRT-LM persistent child process、READY handshake、單 turn Conversation、result / timeout / shutdown。
* 在 backend 實作前建立 `docs/protocol.md` ，至少定義 LiteRT-LM child 的版本、READY、generate、stream / result、cooperative cancel、error 與 shutdown wire schema。
* 實作 child `force_abort()` 的 terminate / kill / waitpid completion proof，以及 RM rebuild / recovery barrier。
* 完成 Button → Listen → ASR → Reasoner → LiteRT-LM → Speak → TTS → Rest 的 Raspberry Pi 5 離線主線。
* 依 `display_spec.md` 將 Baseline 接上實際 startup / IDLE / shutdown、state、主要文字 / 進度與 error 的 sanitized 摘要。

### 6.2 相依

* M3 驗收通過。
* `model_spec.md` 的 M4 baseline 已固定 ASR、TTS engine / model / voice、LiteRT-LM artifact、授權、版本、checksum、Pi 安裝與 benchmark 證據。
* `docs/protocol.md` 的 LiteRT-LM child schema 已 review。

### 6.3 排除項目

* 不讓 LiteRT-LM 自動執行 Python tool handler ；模型只回傳 tool intent。
* 不保留跨 turn / 跨 session 隱藏 conversation history。
* 不實作雲端 LLM、query action 或完整 reasoning loop。
* 不把 native blocking inference 放在主 process thread。
* 不要求 MQTT、voice wake 或 Vision 路徑完成。
* 不加入正式 Display 動畫、圖示或 pixel-level polish ；這些屬 M7。

### 6.4 可重複驗收

1. 在 Raspberry Pi 5 執行：

```bash
python -m pytest -v
python -m pytest -v -m rpi tests/milestones/test_m4_local_voice.py
```

2. 驗收至少證明：
* 固定 WAV fixture 可產生非空 ASR result ；固定文本可產生格式正確的 TTS PCM 並完成播放。
* LiteRT-LM `start()` 只在 READY ACK 後 return ；連續兩 turn 不重載 engine，也不沿用隱藏 Conversation history。
* 模型 timeout / 拒答 / 壞 JSON 在 clean stop 時走 P5 fallback。
* cooperative cancel 失敗時 Level 2 會終止並 waitpid child ；recovery barrier 清除前 SM 不回 IDLE、不接受新 wake。
* rebuild 失敗 / timeout 進 Level 3、exit 4 ；測試結束沒有 orphan child。
* Display 在實際 state、main text / progress、sanitized error、startup 與 shutdown lifecycle 使用 Baseline profile ；Display failure 不阻斷語音主線。
* 整條離線語音 session 不需網路，且 log 不含 transcript、prompt 或 raw model output。
