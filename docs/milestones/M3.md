# M3 規劃

## 5. M3 ── Raspberry Pi HAL 與硬體 bring-up

### 5.1 範圍

* 在 Raspberry Pi 5 實作與驗證：
  * AudioInput / AudioOutput mock/null與real backend；real backend受§5.2.1 Audio P4 package gate約束。
  * Display chip driver、native build 與 `DisplayDevice` 。
  * Camera `picamera2` backend。
  * GPIO `gpiod` backend 與一 pin 一訂閱者原則。
* 實作 Ch 10 的 SSD1351 strict config 與 factory boundary：artifact checksum、ABI v1、SPI0 CE0、GPIO、rotation 0、RGB565 MSB-first 與 32768-byte full-frame 限制必須在硬體前驗證；real backend 才可 lazy load native code。
* 依`DELIVERY-AUDIO-POC-M3-ACK-002`保留Audio Option A契約：direct ALSA `hw:`以48 kHz / stereo / S32_LE開啟INMP441，由HAL顯式選擇channel、解析有效位元、以具anti-alias filter的stateful streaming resampler轉成16 kHz / mono / S16_LE，並只輸出320-sample / 640-byte / 20 ms frames。binding、有效位元alignment、resampler、buffer與async I/O在POC P4通過前不得視為selected implementation。
* 實作 Ch 8 的 renderer、arbiter、slot registry、Presenter / StatusBar 最小 owner 接線。
* 實作 `display_spec.md` 的 selected profile：固定離線字型、Normal 的 StatusBar + Main、state slot、Main fixture，以及 startup / shutdown Fullscreen Blank。
* 提供 Pi local config 範例或部署說明，但不提交真實 pin、credential 或使用者絕對路徑。
* 驗證 real backend 啟動失敗時 audio / display / camera fallback null ；GPIO 不建立 NullGPIO。

### 5.2 相依

* M2 驗收通過。
* 目標硬體接線、chip 型號、ALSA device、CSI camera 與 GPIO 測試 pin 已由使用者確認。
* Pi-only dependency 與 native library 安裝方式已在模組 README 或 setup 文件記錄。
* Audio POC依`DELIVERY-AUDIO-POC-M3-VALIDATION-001`回交target Pi Option A harness、完整source SHA、候選dependency / hash / license / build資料、sanitized config hash及quality / resource / lifecycle evidence；Core Designer核准後才建立production lock。Pi build產生的wheel / `.so`不進Git。
* `display_spec.md` selected profile 已納入 M3 test spec 與 Developer 工作包。

#### 5.2.1 POC contract checkpoints

M3 只依賴 Audio / Display 的 POC contract；真實 LLM 不在本階段 scope，LLM POC contract 不得被列為 M3 開發或驗收 blocker。

M3 採**單一整合進場 gate**：即使 Audio contract 已先 Accepted，也不得拆出 Audio-only、Camera-only、GPIO-only 或其他 M3 產品實作提前開工。Core 可在 Display POC contract 收斂前先完成 `display_spec.md`、mock、字型與 chip-independent 設計；但必須等 Display contract Accepted as design input，且 arch / implement / milestone / Display profile 在同一 M3 Design Ready gate 通過，再完成 test spec 簽核與 Developer 工作包，才正式進入 M3 開發。

| Checkpoint | Audio | Display | 放行規則 |
| :--- | :--- | :--- | :--- |
| **Core Display design review** | Core 已採用初版 Audio contract；後續 P1 native matrix FAIL、P2 PASS 與 Option A change request須另行 disposition | POC pending 不阻擋 `display_spec.md`、mock、字型與 chip-independent contract review；不得把 draft POC 寫成 real-backend baseline | Designer 記錄 Core-owned disposition 與 POC-owned pending condition |
| **M3 Design Ready 前** | Option A產品方向由`DELIVERY-AUDIO-POC-M3-ACK-002`接受；P1維持native FAIL、P2 PASS、P3 Pending M4a，P4 implementation validation Pending | 必須取得可直接對齊 Ch 2a / Ch 8 / Ch 10 的 Accepted design input；lifecycle、ABI、fixture 或 evidence interface blocking finding 均須先解決 | Designer 在 `reviews/milestone_progress.md` 記錄採用版本、ACK / Delivery ID、open conditions 與整合 gate 結論；LLM POC contract 不在此 gate 範圍，不得列為阻擋條件 |

#### 5.2.2 SSD1351 selected deployment profile

M3 只產品化 `DSP-PROFILE-OLED-128`。下表是 Ch 10 strict config 的部署基準；實際值由 Pi local deployment config 提供，不寫入 generic defaults，也不直接複製 POC loader：

| 項目 | Selected value |
| :--- | :--- |
| Controller / canvas | SSD1351 / 128×128 |
| Pixel / orientation | RGB565 MSB-first / rotation 0 |
| Frame buffer | full frame exactly 32768 bytes |
| Native contract | accepted ABI v1；local config 提供 `.so` path 與 SHA-256 |
| SPI | `/dev/spidev0.0`、mode 0、4 MHz baseline、CE0 kernel-managed |
| GPIO | DC=BCM24、RST=BCM25；CE0=BCM8 不得由 GPIO library 重複 claim |

Unknown key、缺欄位、artifact checksum / ABI 不符、非 selected size / pixel / rotation / byte order、超過 4 MHz、超出 ABI v1 signed-int32 範圍的 operator-resolved `gpio_chip_index`、錯誤 SPI / GPIO 組合或 mock/null 攜帶 real-only 欄位，都必須在任何 native import / `dlopen`、GPIO 或 SPI 操作前以 `ConfigValueError` 拒絕。只有合法 `driver=ssd1351` 可進 real factory branch；adapter 將已驗證的 `DisplayConfig.gpio_chip_index` 原樣映射到 ABI v1 `gpio_chip.chip_index`，不得 hardcode 或另讀 global / environment / `GPIOConfig`。startup 後的 native / hardware failure再依 RM policy fallback NullDisplay。

### 5.3 排除項目

* 不整合真實 ASR / TTS / LLM ；硬體測試使用固定 PCM / image fixture 或診斷 worker。
* 不在 P3 TTS winner前替 AudioOutput 加入runtime adaptation；M3 playback fixture直接匹配48 kHz / stereo / S32_LE native output。
* 不等待 LLM POC contract 才開始或驗收 M3；LLM model / runtime / child protocol 屬 M4 entry gate。
* 不實作 wake daemon、MQTT 或 Vision 模型。
* 不實作正式版面資產、開關機動畫、狀態轉場或視覺 polish ；這些屬 M7 後續規格修訂與實作範圍。
* 不加入 LED 表達、touch、OSD overlay 或一 pin 多訂閱者。
* 不以 Windows 測試結果替代 Pi 硬體驗收。

### 5.4 可重複驗收


1. 執行完整純軟體 suite，再於 Raspberry Pi 5 執行：

```bash
python -m pytest -v
python -m pytest -v -m rpi tests/milestones/test_m3_rpi_hal.py
```

2. Pi 驗收至少證明：
* POC P4與Core final selection ACK已完成；AudioInput以direct `hw:`開啟exact 48 kHz / stereo / S32_LE，顯式轉為16 kHz / mono / S16_LE；每幀固定320 samples / 640 bytes / 20 ms，channel selection、核准的valid-bit alignment、clipping與above-Nyquist alias rejection通過deterministic fixture。AudioOutput完整消費匹配native format的固定fixture。
* Camera 依 config 產出合法 JPEG / RGB / YUV bytes 與正確尺寸。
* GPIO register / debounce / unregister / output 行為在指定測試 pin 可重複。
* Display 一次 intent 僅做一組 clear / write / show ；fullscreen ownership、release 與 NullDisplay (0,0) 行為正確；full-frame latency 記錄 P50 / P95，不預設 FPS 或 `<20 ms` 門檻。
* 固定離線字型、Normal 的 StatusBar + Main fixture 與 Fullscreen Blank 可讀；在 Pi 實機確認 rotation 0 方向、RGB565 MSB-first 色彩、無明顯 flicker；startup / shutdown 使用 stable owner 與全黑畫面，且 display failure 不改變主流程或 exit code。
* SSD1351 start / stop / reopen 可重複，invalid config 在硬體前拒絕，stop 後沒有殘留 native handle、GPIO claim、SPI fd 或背景 thread。
* Audio cancel / stop / reopen須重置ALSA stream、resampler與partial-frame state；記錄capture latency P50 / P95 / max、CPU、RSS、temperature、throttling與xrun，結束後沒有ALSA owner。量測值在M3只作baseline；xrun、owner殘留、錯format或錯frame為FAIL。
* 拔除或指定不存在的 audio / display / camera device 後可觀察 null fallback 與 `capability=false` ；GPIO failure 依 required policy 收斂且沒有 NullGPIO。

3. 需要人工觀察的喇叭 / OLED 項目使用固定 fixture 與 checklist，結果記錄硬體型號、config hash、測試時間與 pass / fail ；人工結果不取代可自動檢查的 buffer / 呼叫順序。

4. Button 語意驗收（GPIO 實體 pin，對話按鈕）至少證明：
   * 短按（`short_press_min_ms` ≤ `duration_ms` < `long_press_min_ms`）於 IDLE 產生 `ButtonPressed` Signal，觸發 WAKE 並進入 listen。
   * 短按於非 IDLE 進行中 session（PERCEPTION / THINK / ACTION）產生 `InterruptRequested` 行為，session 收斂後回 IDLE。
   * 長按（`duration_ms` ≥ `long_press_min_ms`）於任意狀態產生 `ShutdownRequested` Signal，App graceful shutdown，exit code 0。
   * 短按於 ERROR 狀態（recovery 已完成或無 recovery）直接進 WAKE，開始新 session。
   * ERROR recovery 尚在進行時短按被忽略；不得產生 `ButtonPressed` / `InterruptRequested` 或中止 recovery，完成後才恢復前一條語意。
