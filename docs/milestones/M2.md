# M2 規劃

## 4. M2 ── Mock 對話垂直切片

### 4.1 範圍

* 將 M1 的 Ch 2 Protocol 套用到本階段所有 mock / null 模組與 worker。
* 實作 Ch 2a 的 mock / null Audio、Display、Camera、GPIO，以及 lazy factory ；不含 Pi real backend。
* 實作 Ch 2b 的 mock ASR、Vision、LLM、TTS，以及 Listen / Read / Look / Reasoner / Speak / Tool / Rest worker 外殼。
* 實作 Ch 7 的 in-memory buffer、`ExternalMessageControl`、`ReadMessageConsumer` 與 read window。
* 實作 Ch 9 的 payload validator、sealed ToolRegistry 與最小 action schema。
* 以 mock config 完成至少兩種可重複 session ：
  * `ButtonPressed` 或 `WakeWordDetected` → listen → reasoner → speak → next turn → rest
  * `ExternalMessageArrived` → read → reasoner → action → rest
* 完成 Interrupt、worker P5 error、SM 自檢 ERROR、normal shutdown 與 buffer flush / discard 的整合路徑。
* `python -m sbd.main` 使用 repository default mock config 可進入 IDLE，收到 shutdown 後乾淨結束。

### 4.2 相依

* M1 驗收通過。
* Ch 9 的 duplicate 敘述已依 §1.2 同步；M2 測試以「SM 去重、只啟動一個 perception worker」為唯一預期。

### 4.3 排除項目

* 不安裝或呼叫真實 Pi HAL、ASR、TTS、Vision、LiteRT-LM。
* 不驗證真實音訊品質、OLED 畫面、CSI 影像或 GPIO 電氣行為。
* 不連接 MQTT broker ；外部訊息由測試直接呼叫驗證後的 `ingest()` 。
* Tool 只用 deterministic fake handler，不控制實體設備。
* 不建立 wake daemon ；voice-wake Signal 由 mock InputSource 產生。

### 4.4 可重複驗收

1. 執行：

```bash
python -m pytest -v tests/milestones/test_m2_mock_pipeline.py
python -m pytest -v
python -m sbd.main
```

2. 自動化驗收至少證明：
* 兩種 session 均依序觀察到 IDLE → WAKE → PERCEPTION → THINK → ACTION，並在 rest 後回 IDLE。
* 每個 operation 恰走 normal / P5 / exception / cancel 其中一條路徑，沒有重複 terminal Fact。
* speak / tool 的 duplicate `next_perceptions` 去重後只啟動一個 worker ；rest 完全忽略該欄位。
* Interrupt 在 `_TaskCompleted` 尚未被 SM 消費時不會提早回 IDLE。
* read window 的 begin / consume / close race 不遺失訊息；rest 在回 IDLE 後 flush-to-wake，error / interrupt / shutdown discard。
* mock backend 的 `force_abort()` 符合純 asyncio completion proof，且不留下 task。
* default mock 啟動不需要 Pi-only 套件、網路、模型檔或使用者 credential。

3. `python -m sbd.main` 的人工 smoke 只補充自動化驗收：啟動 log 顯示 IDLE，`Ctrl+C` 後 exit 0 ；它不可取代前述測試。
