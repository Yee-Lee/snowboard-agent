# M7 規劃

## 9. M7 ── Display UX 完整化

### 9.1 範圍

* 實作 `display_spec.md` Complete profile 的正式 StatusBar、main、fullscreen 版面、字型、圖示與離線資產。
* 實作開機、關機與狀態轉場動畫，以及字幕、進度、音量、連線、能力與 sanitized error 的完整呈現。
* 動畫 client 具取消、上限與 `finally` release ；沿用 Ch 8 同步 arbiter、stable owner、不排隊與 Display failure 非阻擋規則。
* 在目標 OLED 驗證可讀性、更新效能、閃爍、長時間顯示與重複 lifecycle 收斂。

### 9.2 相依

* M6 驗收通過。
* 目標 OLED chip、resolution 與 orientation 已固定。
* Complete profile 的正式 layout、字型、圖示、動畫方向、資產授權與人工 checklist 已由使用者確認。
* M7 的 test spec、Developer 估點與工作包已完成。

### 9.3 排除項目

* 不新增 touch、LED、adjuster overlay、跨 owner fullscreen preemption 或新 Display 角色。
* 不改變 SM 狀態、worker 行為或 tool / message / model 契約；Display 只觀察與表達。
* 不把本階段等同 release packaging ；systemd image、OTA 與正式發行另案規劃。

### 9.4 可重複驗收

1. 在 Raspberry Pi 5 執行：

```bash
python -m pytest -v
python -m pytest -v -m rpi tests/milestones/test_m7_display_ux.py
```

2. 驗收至少證明：
* 所有核准 state、StatusBar slot、main 與 fullscreen 畫面符合 Complete profile。
* 開機、關機與狀態轉場可取消且有上限；競爭 owner 仍拒絕、不排隊。
* shutdown、fatal、renderer failure 與 NullDisplay 不留下 fullscreen owner / animation task，也不改變既有 exit code。
* 人工 checklist 記錄硬體、resolution、資產 revision、config hash、時間與 pass / fail ；人工結果不取代 ownership、timeout 與 cleanup 自動化測試。
