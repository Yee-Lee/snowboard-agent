# P1.1-PI-STARTUP-ATTRIBUTION-PACKET-001

- **Status**: `NON-SCORING ENGINEERING DIAGNOSTIC`
- **Gate/P credit**: `FORBIDDEN`
- **Source finding**: Gate 1 Run 004 proved both frozen candidates exceeded the M4B-P1 10-second
  READY deadline after one-pass model authentication had completed.

## 1. Purpose and boundary

P1.1 attributes cold-child startup time and tests whether work currently done before READY is
required for an immediately usable child. It never changes the formal P1 deadline, never overwrites
Run 004 and cannot select or backfill a finalist. A profile is viable only if it emits exact-identity
READY, answers PING, completes one frozen minimal generation, acknowledges SHUTDOWN and leaves no
process group.

## 2. Measurement map before analysis

| Work | Clock placement | Measurement responsibility |
| --- | --- | --- | --- |
| Full model SHA-256, wheel install, ELF/linkage and custody | before P1 | create a fresh run-scoped receipt and record outside-clock preparation only |
| Spawn and adapter entry | P1 | measure spawn-to-main |
| Config/receipt metadata | P1 | measure exact-identity work |
| LiteRT import | P1 | measure Python/native library import |
| CPU Engine and model initialization | P1 | measure unchanged constructor as one native-owned stage |
| Sampler construction | P1 | measure unchanged sampler stage |
| Protocol validator | P1 | measure schema/resolver construction |
| READY write/flush | P1 | measure exact protocol emission |

No action is called necessary, deferrable or removable from timing alone. P1.1 first records every
current stage and validates the unchanged child through generation and shutdown. Variant selection
and necessity analysis happen only after the baseline evidence is reviewed.

## 3. Frozen baseline execution

For each frozen candidate, condition the page cache outside the startup clock using drop advice plus
the fresh receipt's one authenticated sequential read, then run exactly one `baseline` profile with
unchanged Engine arguments. A receipt from an earlier run is never reused because its immutable file
metadata may no longer match after that run restores artifact permissions.

Each profile records child spawn-to-READY and monotonic durations for config/receipt, LiteRT import,
Engine construction, sampler, protocol validator and READY emission. The 120-second outer bound is
diagnostic only. `p1_contract_fit=true` requires READY at or below 10,000 ms plus PING, RESULT,
SHUTDOWN_ACK and clean process-group proof.

## 4. Post-measurement boundary

- First publish the baseline stage table without a removal recommendation.
- Analyze semantic necessity only after the User reviews the measured table.
- Freeze any bounded-context, benchmark, sampler or runtime-owned experiment as a separate P1.1
  follow-up before running it.
- Never move Engine construction after READY merely to make the clock green.
- Any adopted startup change requires a new prospective source/config freeze and new Gate 1 run;
  P1.1 itself is not a retry and produces no acceptance result.
