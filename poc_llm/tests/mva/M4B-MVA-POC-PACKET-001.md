## Frozen method inherited from the delivered request

The execution snapshot binds the MVA profile, exact prompt/template bytes, semantic and wire
schemas, public catalog, runner, result schemas, ordered repetitions and scope exclusions in a
non-recursive surface manifest. The baseline uses one Conversation per product session, normal
two-turn reuse, compact `text/end`, and no disposable pre-warm. The only A/B variable is public
disposable pre-warm `none/once`; its Conversation is closed before opening the product session.

Cold order is exactly `N1/O1/N2/O2/N3/O3`; replacement order is exactly
`N1/O1/N2/O2/N3/O3/N4/O4/N5/O5`. Timing input is the public two-turn sequence
`天空為什麼是藍色的？` then `再簡單一點。`; pre-warm input is `請用一句話打招呼。`.
Samples are descriptive and report each value plus median/range, never a small-sample P95 claim.

Memory uses three fresh-child cycles of 20 complete two-turn sessions. Sessions 11–20 are the only
steady analysis window. Each cycle reports owner PSS and system-used raw values, OLS slope,
sessions 11–15 and 16–20 medians, and late-minus-early delta. Controlled recovery is three separate
`capacity_test` requests from READY_NO_SESSION; it is not manufactured memory pressure and does not
alter the natural soak.

## Executable surface and claim limits

Entrypoint: `python3 -m poc_llm.tools.run_mva`. The controller launches a fresh Python child/Engine
with a run-owned temporary cwd, at most one active RPC, and one Conversation per product session.
Its private JSON RPC is POC orchestration; the tracked `snowboard.llm/2` schema remains the Core
boundary reference, but this RPC is **not** Core protocol-conformance evidence. It includes process IPC,
session open/close, parse/validation and deterministic Reasoner projection in caller TTC. It does not
simulate the Core event loop, dispatch queues, watchdog implementation, Audio or product scheduling.

Prompt/template files are passed without newline stripping. All public catalog inputs are counted
with the selected Engine tokenizer before any inference. Out-of-range input is Blocked. `api-proof`
performs two normal turns and close, a separate cancellation observation, then a fresh two-turn
session; it must observe typed CANCELLED and successful fresh-session use. A generation completing
before the fixed 50 ms cancellation request is Incomplete, not native-cancel proof or a retry license.
Render/incremental/KV/output values come from the selected runtime, not a host tokenizer.

The no-prewarm profile remains the delivered baseline for memory and recovery. A/B results do not
automatically select or tune a profile; any proposed change requires User review and a new snapshot.
Semantic model output exists transiently in worker/controller memory only. No raw/native stdout,
stderr, prompt or answer is written. Resource readings occur at startup, during work (one-second
cadence), each turn and session close. Sampler subprocess calls each have a three-second timeout;
sampler work is POC overhead and its timing cannot be subtracted post hoc to claim product parity.

The current scope is strictly `llm_subsystem`; Audio digest and audible latency remain null. ALSA
cleanup is not applicable to this LLM-only runner and remains null, never a fabricated zero.

The accepted runtime is a CPython virtual-environment layout. The runner derives the import root from
the authenticated native-library path, compares the selected wheel to that exact package tree and gives
the child the derived `site-packages` root. The authenticated content-addressed model object remains the
original `payload`; each child receives a run-owned temporary `.litertlm` symlink to the same inode because
the native loader requires that suffix. The presentation link is removed during run cleanup.

LiteRT-LM v0.16 LLGuidance does not implement JSON Schema `if/then/else`. The native constrained schema
therefore freezes only the supported exact-object/type/length constraints, while the existing Python
semantic validator still rejects `end=false` with blank text and `end=true` with nonblank text before any
result is accepted. Evidence identity includes the authenticated product-storage digest and cache key.

## Initial install verification and same-install trust

An operator-held JSON config outside Git contains exactly `model_path`, `runtime_root`,
`runtime_wheel` (absolute non-symlink paths) and positive integer `install_generation`. It contains
no inference overrides. The selected profile supplies 32/128/1024, CPU/4, temperature/top-p and

installed `litert_lm/` bytes to the exact selected wheel, hashes the full runtime tree and model,
requires read-only files, and stores device/inode/size/mode/mtime/ctime identities. The receipt
contains local paths and stays outside Git under mode 0600.

Perform initial full verification **before** the six measured cold reboots. Each later launch and
resource check validates the operator-held receipt digest and unchanged metadata, without a full
model rehash. The worker additionally checks actual `litert_lm` import origin. Same-install recovery
uses identical config/receipt and launches the replacement only after old owner-group absence.
This metadata trust assumes an operator-controlled read-only installation; it is not protection
against a privileged actor deliberately forging both artifacts and receipts.

## Failure, durability and cleanup

Every accepted run ID reserves a new directory; rerunning it fails closed. `checkpoints.jsonl`
fsyncs schema-validated same-shape observations with cleanup pending; `samples.jsonl` then appends
final copies after child cleanup. They are separate artifacts: checkpoint rows are not additional
timing samples. A crash leaves checkpoints plus no completion summary; do not infer PASS or continue
the ledger. `summary.json` contains per-cycle fixed-window statistics, token census and cleanup
receipts; ledger rows bind summary checksum, identity, case and boot. Incomplete/failed cases halt
the matrix pending review, and retain all samples. There is no automatic rerun or backfill.

An independent receive watchdog requests cancel at the frozen deadline and force-aborts the owned
process group after two seconds even if the main-thread resource probe stalls. RPC writes are also
bounded (one second); output frames are limited to 64 KiB. Generation timeout or failure requests
native cancel (the backend invokes native cancel at most once), waits at most two seconds for convergence,
then cleanup requests SHUTDOWN (ten seconds) and wait (two seconds), followed by process-group
TERM/wait and KILL/wait (two seconds each). Absence of all owned process-group PIDs is checked;
forced cleanup never converts a failed run to PASS. Cleanup failure prevents replacement and
all later work. Ctrl-C follows the same cleanup path. Native crashes/unknown exceptions are typed
without echoing exception text. Power loss cannot establish cleanup; retained checkpoints require
operator review. No retry is allowed under this run ID. Hardware status remains subject to evidence
review even when the runner returns PASS.
